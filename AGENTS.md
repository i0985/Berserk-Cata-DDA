# Работа с Berserk 3.4

- Рабочая ветка: `3.4` в `i0985/Berserk-Cata-DDA`. Исходный снимок — `0950c57c2601e320a45eb048b9e6d2cd74b070d1`. Не менять `3.3-apostol-test` и другие ветки без отдельного указания владельца.
- `mods/Berserk` и `mods/Berserk_chibi_tileset` — канонические исходники. Не пересоздавать их скриптами восстановления из 3.3 и старыми сборщиками. Оставшиеся модули `*_33.py` с источниками для проверок и локализации не являются обязательным конвейером сборки.
- Игровой текст: английский в JSON, русский в gettext, существующий китайский сохранять. Сохранять контексты и формы множественного числа, обновлять скомпилированные каталоги. Авторские спрайты и атрибуции сохранять.
- Проверять ссылки перед удалением: учитывать нативную генерацию, copy-from, вложенные эффекты, сохранённые ID карт, персонажей и отложенных событий. Присутствие ID только в старой документации не означает, что он нужен игре. Для объединения старых предметов использовать миграцию.
- Сохранять активные сюжетные маршруты, прогресс, заказы, координаты и состояния NPC. Не считать старые карты ненужными только потому, что новые миры их не выбирают.
- Перед публикацией запускать команды из README. Отдельно указывать проверки данных, сценарные модели и игровой тест. Публиковать рабочие коммиты в 3.4 и сверять удалённый SHA; не считать локальный коммит выгрузкой.
- Решения и состав уборки: `docs/cleanup-3.4.md`, точные списки — `docs/cleanup-3.4.json`. Подробные прежние правила и инструменты доступны в зафиксированном снимке 3.3.
