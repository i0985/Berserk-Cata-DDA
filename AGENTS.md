# Работа с восстановленной 3.3

- Каноническая рабочая ветка этого восстановления: `3.3-apostol-test` в `i0985/Berserk-Cata-DDA`.
- `mods/Berserk` и `mods/Berserk_chibi_tileset` восстановлены из архива владельца. Старые генераторы 3.2 не являются источником данных 3.3: не запускать их поверх этих папок без проверки изменений.
- Сохранять каждый законченный пакет на GitHub. Локальный коммит без отправки не считать опубликованным или сохранённым удалённо.
- Если обычный `git push` недоступен, использовать подключение GitHub: создать blobs/tree/commit, обновить ветку без force с ожидаемым SHA, проверить удалённый SHA и совпадение дерева. Не менять существующие ветки пользователя.
- В отчёте всегда различать проверки данных, моделирование событий и настоящий игровой тест. Не объявлять старые проверки 3.2 актуальными для 3.3 без адаптации.
- Сценарии Годо и Рикерта из документов от 21 октября согласованы владельцем для переноса. Остальные новые сценарии октября остаются отдельным этапом. Позднее владелец разрешил ванильное доверие, восстановление кисти демоническим изменением и редкий протез: актуальный результат в `docs/apostol-body-trust-2026-10-21.md`.
- Для нового дерева Годо источник — `docs/dialogue_sources/godo-2026-10-21.json`, сборщик — `tools/build_godo_dialogue_33.py`. Старые `recover_*_33.py` восстанавливают архив и не должны запускаться поверх утверждённых новых диалогов. Сборщик ремонта сохраняет новый литературный текст.
- Для нового дерева Рикерта источник — `docs/dialogue_sources/rickert-2026-10-21.json`, сборщик — `tools/build_rickert_dialogue_33.py`. Общий файл диалогов кузни сохраняется. Пересборка: сначала Годо, затем Рикерт, затем `tools/build_apostol_body_rules_33.py`. Доверие — штатное `n_npc_trust()`, не счётчик заказов. Пожизненный отказ не снимается ростом доверия.
- Кисть восстанавливается один раз при первой фактической демонической мутации мода; отказные шрамы, наличие Бехелита и ванильные мутации не подходят. Не удалять установленную пушку, её боеприпас, Клеймо или глаз. Не подменять резерв пути ритуала готовой игровой цепочкой: ритуал ещё не реализован.
- Сценарий Рыцаря-Черепа согласован 22 октября: `docs/dialogue_sources/skull-knight-2026-10-22.json`, сборщик `tools/build_skull_knight_dialogue_33.py`. Удалена категория практической помощи; «Поможешь мне?» даёт один короткий ответ. Первая охота остаётся автоматической. «Где искать зло?» не открывает журнал и не запускает поиск. Рыцарь уходит только после подтверждённого прощания. Флору и будущую встречу после дара в его текущий разговор не возвращать.
- После прежних трёх сборщиков запускать `build_skull_knight_dialogue_33.py`, затем `build_direct_hunt_missions_33.py`. Новые известные направления запускают обычные миссии при сюжетном событии; бумажный журнал не является условием. Старые координаты не переносить ради расстояния. Не добавлять неподдерживаемые ключи размещения в JSON: ограничения текущего штатного механизма разобраны в `docs/journal-missions-rework-2026-10-22.md`.
- После прямых миссий запускать `tools/build_flora_dialogue_33.py`, затем сборщики пленника и именованных апостолов, последним — `tools/build_reference_journal_33.py` (всего девять). Источник Флоры — `docs/dialogue_sources/flora-2026-10-22.json`. Последние решения владельца заменяют прежнюю отдельную готовность получателя брони: новая выдача запускает нападение через 3 игровые секунды, оберег больше не запускает сцену. Для владельца комплекта, отказавшегося от брони и демонического героя остаётся одно решение продолжить. Договор завершает миссию отдельным успешным исходом, не меняет флаги смерти, разлом и награды. Новая сохранённая запись Флоры ещё не согласована; не добавлять её в рукопись.
- Утверждённый макет справочника — `docs/dialogue_sources/road-journal-2026-10-22.md` и его JSON; привязки — `tools/reference_journal_content_33.py`. Книга только хранит изученные сведения: не добавлять в её меню поиск, выдачу заданий, наград, смену пути или восстановление сцен. Физические источники читаются отдельно, их архивные копии не повторяют эффекты. Сохранить порядок первого изучения и независимость прогресса от наличия книги. Изменения и приёмка: `docs/reference-journal-2026-10-22.md`.
- Сохранять существующие ID, координаты, выданные награды и постоянные превращения. Не удалять уже полученное снаряжение.
- Плейтест 23 октября: проект `docs/location_projects/flora-3.3-03.json` — утверждённые клетки по красно-синей разметке владельца. `build_flora_treehouse.py` экспортирует v3 и диспетчер осады, не перезаписывает старые v0/v1/v2-патчи и не перестраивает посещённые карты. Стены и мебель меняются через проект; точки сцены берутся оттуда же.
- Дом Флоры больше не размещается естественно: `occurrences: [0, 0]`, сюжетный поиск/создание допускается только после возвращения из Затмения. Ранние известные координаты сохраняются, но не обходят это условие.
- После девяти сюжетных сборщиков запускать `tools/apply_visual_fallbacks_33.py`: он применяет проверенный список неподходящих `looks_like`, сохраняя авторские mod_tileset и подходящую обычную мебель. В абзацах действий Годо использовать `&`, если имя уже находится в тексте: нативный `*` добавляет имя сам.
- Пленник Графа согласован 23 октября: `docs/dialogue_sources/count-prisoner-2026-10-23.json`, сборщик `tools/build_count_prisoner_dialogue_33.py` запускается после Флоры, перед апостолами и справочником. Это настоящий NPC по образцу `mi-go_prisoner` 0.I, с родными follow/flee, без отдельной миссии сопровождения. Новые карты помещают его за запертую решётку существующей западной камеры на первом этаже. Ключ остаётся в сундуке писаря и открывает камеру и прежний обход; из разговора ключ не выдаётся.
- Смерть Графа, доступная камера и выход пленника за периметр — разные состояния. Справочник не отмечает спасение от одного разговора о смерти. Старого монстра заменять только после успешного создания уникального NPC; не перерисовывать посещённую тюрьму, не воскрешать погибшего и не создавать копию уже ушедшего NPC.
- Именованные апостолы согласованы 23 октября: `docs/dialogue_sources/named-apostles-2026-10-23.json`, сборщик `tools/build_named_apostle_dialogues_33.py`. Последние ответы владельца заменяют пометку документа об угасании помощи: смерть хозяина обрывает помощь сразу. Превращение мгновенное, поставка даёт шесть часов сразу. Отмена возвращает к выбору, не приравнивается к отказу. Нападение игрока, спутника или союзного источника разрывает договор; временные скрытые признаки перемирия защищают NPC-спутников от соответствующего хозяйства, без смены их тела и без приручения боссов. Принадлежность Чёрных Псов не должна наследовать хозяйство Графа. Не добавлять человеческие фазы боссов или новые формы Гатсу; сохранять исходы охот и судьбу оригинала Грюнбельда.
