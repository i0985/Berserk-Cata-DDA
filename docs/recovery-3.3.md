# Восстановление 3.3-apostol

## Исходный снимок

- Источник: `Berserk-3.3-apostol-math-load-fix.zip`, предоставлен владельцем проекта 2026-10-20.
- SHA-256 архива: `320e5223f0c94cb05d33e98d752e4eaf7b584e0c1c92ddf535e46e9dc8efbb6f`.
- 403 файла в двух пакетах: `mods/Berserk` и `mods/Berserk_chibi_tileset`.
- Первоначальный коммит восстановления сохраняет байты всех файлов архива без изменений.
- Служебные скрипты и проверки унаследованы от 3.2; они НЕ являются восстановленными генераторами 3.3. Не запускать старые генераторы поверх данных 3.3 без отдельного анализа.
- Старые локальные коммиты `97c769a` и `baf2b05` отсутствуют на сервере; последующие исправления восстанавливаются отдельными новыми коммитами, а не выдаются за прежнюю историю.

## Порядок сохранения

1. Локальная папка используется только для редактирования и проверок.
2. Каждый законченный пакет коммитится и отправляется в `3.3-apostol-test`.
3. После отправки сверяются локальный SHA и удалённая ссылка GitHub.
4. В отчёте о завершении указываются ветка, коммит и результат проверок.
5. При недоступности отправки работа не объявляется сохранённой на GitHub.
6. Новые литературные сценарии диалогов октября не включаются в этот этап.

## Проверки исходного снимка

- Проверка assets: успешно, 352 JSON, 2 пакета, 4 каталога переводов.
- Унаследованный полный набор 3.2: 322 теста, 95 failures и 69 errors на исходном архиве до исправлений. Среди причин — изменённые состояния/планировки и неполные старые интерпретаторы EOC. Это не считается успешной проверкой 3.3.
- Старые тесты не удаляются и их красный результат не скрывается. Для восстановленных правил добавляются/адаптируются отдельные актуальные проверки.
- Нативная загрузка, анимация, AI, распространение огня и игровой баланс требуют игрового прогона в целевой CDDA; проверки Python его не заменяют.
