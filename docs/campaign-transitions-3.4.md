# Переходы кампании Berserk 3.4

В таблицах описаны основные переходы, которые влияют на задания, награды и повторный вход в сцену. Названия состояний соответствуют условиям в данных мода для CDDA 0.I-1.

## Флора

| Откуда → куда | Условие | Что видит игрок |
| --- | --- | --- |
| Знакомство → мирный разговор | Встреча у зарегистрированного дома. Для поздних тем нужно завершённое возвращение из Затмения и зачтённые охоты на Графа, Уайлда и Розину. | Открываются темы подготовки. Доступный дар пополняет недостающие части комплекта один раз. |
| Мирная сцена → подготовлено, в очереди | Подтверждение дара или готовности в зарегистрированной роще. Реплика готовности и её обработчик используют `CAN_PREPARE_SIEGE`. | Разговор завершается и запускается отсчёт на три игровые секунды. Вне рощи устаревшее действие даёт пояснение о возвращении и оставляет очередь пустой. |
| Подготовлено → активная осада | Время истекло, герой в зарегистрированной роще, мирная стадия подготовки подтверждена. Для обеих веток используется `FLORA_ECLIPSE_SURVIVOR`. | Грохот и первая волна. Вторая свита предусмотрена через 20 секунд после первой. |
| Активная осада → побег засчитан | Герой покинул зону осады. На поверхности граница проходит в 32 клетках от зарегистрированного центра. | Появляется итог побега. Пожар продолжает менять карту, осада прекращает добавлять врагов. |
| Побег → повторная загрузка или возвращение в рощу | Сохранена стадия побега 5. | Нападение уже завершено. Сценарий доводит пожар до финальной фазы. |

## Проверка движком

CI запускает оба пакета в одноразовых мирах. Терминальная CDDA 0.I-1 закреплена по SHA-256 архива и ревизии двигателя `7b2efa5`. Каждый результат в журнале содержит версию, сид `EarlyGuts34`, входное состояние и отметку, которую вывел движок после проверки.

| Сценарий | Игровое подтверждение |
| --- | --- |
| Ранний старт | Запустилась профессия раннего Гатса с мечом и характеристиками 10/10. |
| Обычное спасение | До подтверждения прибытия спасение ждёт переноса. После подтверждения установлено Клеймо, изучены рецепты и закрыто состояние испытания. |
| Альтернативное возвращение | На обычном выжившем проверен отказ от дара. Без подтверждения клетка не засчитывается. После безопасного прибытия открывается продолжение. |
| Осада | При выходе с первой фазы засчитывается побег. Через заданный интервал пожар достигает финальной фазы без новой свиты и повторных попыток появления апостолов. |
| Пепельный разрыв | Пока закрытой мебели нет, флаг запечатывания не меняется. После обновления карты движок видит закрытый след и фиксирует зачёт. |

Ранний старт проходит через штатное создание персонажа. Для последующих переходов сценарий задаёт входное состояние и вызывает штатный обработчик. Для этого сида журнал может фиксировать повтор поиска кузни или первого логова. Сценарий продолжает проверку после этих двух сообщений. Ошибки загрузки данных завершают проверку.

## Замер 100 игровых ходов

Запуск CI вручную добавляет три замера на том же бинарнике. Замер начинается после подготовки сцены. Штатное действие ожидания двигает игровые ходы, отдельное событие отмечает 100 ходов по часам игры. Локальные результаты приведены в секундах.

| Сцена | До правок, CPU / всего | После правок, CPU / всего |
| --- | ---: | ---: |
| Обычный мир | 0,12 / 0,347 | 0,14 / 0,372 |
| Сектор прибытия в Затмении | 0,15 / 0,361 | 0,14 / 0,352 |
| Активная осада Флоры | 0,17 / 0,402 | 0,18 / 0,397 |

Замер в осаде использует неподвижного героя и блокирует новые появления апостолов и свиты. Это сравнение работы сцен с одинаковыми входными условиями. Время до и после включает отрисовку терминала, а CPU относится к процессу игры целиком. Один замер на сцену не позволяет измерить эффект отдельных обработчиков.

После исходной серии поиск Грюнбельда для отметки встречи получил условие начавшейся осады. Проверка спасения сначала смотрит, активно ли Затмение, и только затем проверяет карту. Это убирает вызовы вне подходящих состояний. Разница серий находится на уровне сотых долей секунды, поэтому у CI нет порога производительности.
