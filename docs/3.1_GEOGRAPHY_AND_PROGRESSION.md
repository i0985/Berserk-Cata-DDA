### Limits that matter for this repair

* `min_distance` filters a lookup. It is not forwarded as a lower bound to
  `place_special`. Passing both a minimum and a special therefore cannot promise
  a newly created location outside that minimum.
* `var` is an already chosen target, not a custom search origin. A location EOC
  without a mission cannot use it to search from an arbitrary saved clue.
* The JSON parser rejects explicit `search_range` when `random` is false.
  Without the explicit key the parsed default is 540 OMT. Closest lookup stops
  at the first matching distance; it does not collect a random sample across the
  whole search square.
* `create_if_necessary` exists inside the C++ structure but is not parsed from
  mission target JSON here. It must not be added as a JSON field.
* A failed `get_om_terrain_pos` can leave the EOC with the player's origin and
  still reach its success callback. Registration must validate terrain and z
  before creating the mission. A nonempty coordinate is insufficient.
* Replacing an overmap terrain ID does not replace an already generated local
  map. Native special placement excludes explored placement sectors; the mod
  does not repaint visited maps to fabricate a destination.

## Implemented geography prototype

The four Behelit sites retain their existing natural placement, biome rules and
independent caches. Their post-Eclipse reward gate is unchanged.

Count, Wyald, Rosine, Flora and Grunbeld now participate in normal overmap
generation: existing IDs, `GLOBALLY_UNIQUE`, occurrences `[1,1]`. This requests
one natural placement in an eligible region; lack of a valid footprint can still
prevent that attempt. Their direction handlers search for existing terrain,
using native closest lookup. No `om_special` or `om_terrain_replace` is supplied
by those handlers, so they cannot forcibly insert the destination next to the
player. If necessary the native lookup generates further overmaps naturally.

This deliberately differs from vanilla's mission-forced insertion after search:
that insertion cannot enforce the requested lower distance. Normal worldgen is
the supported creation path for these five named sites in this prototype.
They can be physically discovered before their recommended mission stage.

First hunt and first breach remain mission-placed small encounters. Their first
lookup/creation caps are 16/24 OMT, with bounded fallback caps 32/48. The lower
bound is not guaranteed by native creation. An already known site is reused.

| Place | Requested travel guideline | Current guarantee |
| --- | --- | --- |
| First hunt | 8–16 from return | Small quest placement; no strict minimum. |
| First breach | 12–24 from first lair | Small quest placement; no strict minimum or arbitrary source-origin search. |
| Count / Wyald / Rosine | 40–80 from the clue | Naturally distributed unique site; this ring is not enforced. |
| Flora | 80–140 from the late clue | Late directions to a naturally distributed unique grove; this ring is not enforced. |
| Fortress | 60–100 after Flora | Post-siege directions to a naturally distributed unique fortress; this ring is not enforced. |

**Strict source-centered distance bands are outstanding work.** Implementing
them requires a separately verified mechanism to select a valid footprint
around a stored origin before placing the special. Increasing a search number,
rejecting a successfully placed unique, or pretending `var` changes the origin
is not an acceptable substitute. This build tests natural distribution first.

Old saved coordinates, visited maps and original IDs stay. Placement retry
markers are versioned to reopen previously exhausted searches after updating.
Coordinates are validated and stored before the mission is assigned to the same
site. An existing unique beyond the bounded terrain lookup may remain unavailable
from a new, distant clue; keep the clue and retry after further travel. Failed
searches can still produce the engine's diagnostic; the mod cannot suppress it
from data alone.

## Progression and relic

Recommended sequence:

1. Eclipse, rescue and first hunt.
2. Ashen breach and independent Count/Wyald/Rosine hunts.
3. Close all three named breaches (state 4 or 5), obtain Flora's directions.
4. Peaceful grove, armor, explicit siege preparation and escape.
5. Grunbeld fortress and unfinished objectives.

The first hunt no longer requests Flora. Each of the three seals checks the
late clue immediately. A one-minute fallback supplies it after returning to the
surface if the last seal was underground. Directions are not consumed on a
failed lookup. Known valid groves remain usable for saved games and physical
discoveries; no armor is taken away. Existing fortress registrations also remain
usable before the new recommended sequence. A newly recommended fortress route
requires the siege to have ended. Entering a physically discovered arena still
registers its location normally, except during the active siege.

The Beast Knot retains its item ID and worn relic slot. It now uses the native
enchantment `NIGHT_VIS` with `add: 2`; no armor requirement. A backpack alone does
not activate it. New Berserk activations last 150 seconds with or without the
Knot. An already active old 210-second rush is allowed to finish normally.

The native vision modifier changes dark vision range before lighting and limb
scores are applied. Injury, visibility and walls still matter. This engine's
legacy night-vision bionic/goggle branch bypasses `NIGHT_VIS`; the Knot is not a
promise of two extra visible tiles on top of those devices. Test ordinary night
sight first, with the post-Eclipse eye state also noted.

No new boss-stat changes are claimed here. Count, Wyald and Rosine must be
playtested with a prepared ordinary survivor, conventional armor, good weapon
and optional cannon prosthesis, without Berserk armor. The 20/20 start is a
separate strong loadout. Adjust actual failed attacks or excessive damage after
that comparison rather than compensating with infinite HP/regeneration.

## Grunbeld after the siege

The reported missing boss has not been reproduced in the native game. These
changes protect the transition without interpreting absence as death:

* Escape records withdrawal of the grove actor immediately, including when it
  has already unloaded. Loaded actors are retired with `u_die`'s tracker-removal
  path, which returns before native death callbacks or loot.
* A reload cleanup handles an old grove actor when it becomes loaded again.
  A withdrawn actor cannot later set the original's death flag or drop a second
  shard. Actual grove death before withdrawal still records the original death
  and puts exactly one shard at the body position, without relying on a killer.
* Active siege blocks starting a parallel fortress encounter.
* Fortress arrival only commits and announces after a knight is confirmed in
  the loaded neighborhood. Failed presence verification takes the bounded arena
  retry path. Form tags record the last confirmed position/time; tagging a
  dragon repeatedly does not repeat its initial recovery cost.
* A wounded existing fortress boss is retained. A confirmed dead original is
  not resurrected. An old `spawned=1` without any surviving proof is not reset
  merely because no monster is nearby; such ambiguous saves need inspection.

## Verification and playtest

Automated checks here use JSON, assets/catalog validation and small event/talker
models. They are not native worldgen, combat, vision or savegame tests.
`tools/test_new_horizon_31.py` covers late directions, deferred recovery, saved
Flora coordinates, failed target validation, arena confirmation, withdrawal,
real death, retained wounded boss, post-siege route and relic activation data.

Required native pass:

1. New world: four Behelit sites appear naturally; named sites spread across the
   world, with local maps matching the markers. Record actual OMT distances.
2. First hunt alone does not give Flora. The third named closed breach supplies
   directions, including when it is closed underground then the player emerges.
3. Old save: known grove and fortress coordinates stay; old armor and trophies
   stay; no second unique, boss or reward after reload.
4. Night: compare Knot worn / backpack / removed, with the same light and eye
   state. Check that a new rush stays 150 seconds.
5. Escape normally, then repeat the user's immediate debug teleport to the
   fortress. Enter the inner arena: one knight, then one dragon, no dead flag
   caused by withdrawal. Retreat and return: same wounded original.
6. Kill the grove original before escape: fortress has the remaining breach
   instead of a second living original; there is only one shard.

Keep the original save backed up when doing debug teleports. The exact nightly
loader and in-game transitions remain unverified until this pass.
